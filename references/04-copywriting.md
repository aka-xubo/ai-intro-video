# 口播文案与音视频规范

## 口播文案通用规范

### 文案风格
- **口语化**：像跟朋友聊天，不是念稿。用"你"不用"您"，用"聊聊"不用"探讨"
- **有态度**：表达者可以有鲜明观点人，不是中立的播报员
- **具体化**：用数字、用例子、用场景，不用空洞的形容词
- **节奏感**：长短句交替，重要信息前留停顿

### 文案禁忌
- ❌ 技术术语堆砌（除非是概念科普类，且会解释）
- ❌ 绝对化表述："一定"、"必须"、"永远"、"从不"
- ❌ 营销腔："震惊！"、"颠覆！"、"必看！"
- ❌ 过长的句子（单句不超过 25 字）
- ❌ 没有信息量的过渡句："接下来让我们看看..."

### 文案结构通用要求
- 每个场景的口播文字必须清晰标注
- 按场景分段，标明场景编号
- 标注预估时长（秒）
- 标注情绪/语气提示（如：好奇、感叹、轻松）

## 分镜脚本格式

每个镜头包含：
- **镜头编号**
- **时长建议**（秒）
- **画面元素**（背景/主标题/副标题/图形/图标）
- **动效提示**（淡入、位移、缩放、弹性等）
- **屏幕文字**（与口播同步的关键词/短句）
- **对应口播句子**
- **字幕分段**（按句号分割的 segments）
- **序号指示器**（如果场景包含有序列表内容）

按"封面-片头-主体-片尾"分段输出，保证镜头数量与口播语义一致。

## 序号指示器规范（CRITICAL）

### 触发条件

当一个场景包含**有序列表内容**时，必须在画面固定位置显示序号指示器。判断标准：
- 口播中出现"第一、第二、第三..."或"01、02、03..."
- 场景内容是一组并列的步骤、原则、事件、建议等
- 总数 ≥ 2 项

### 固定位置

右上角，距离顶边和右边各 **60px**。不随内容滚动，始终固定在画面上。

### 视觉规范

```
┌─────────────────────────────────────────────────────────────────────┐
│                                                          ┌─────────┐ │
│                                                          │ 01 / 03 │ │
│                                                          │ 看changelog│
│                                                          └─────────┘ │
│                                                                       │
│                    主体内容区域                                        │
│                                                                       │
└─────────────────────────────────────────────────────────────────────┘
```

- **容器**：暖纸编辑式标签，`background: rgba(255,253,248,0.82)`，顶部 `3px` 当前语义色，底部 `1px solid #C9C1B2`，不使用圆角和阴影
- **序号行**：`当前序号 / 总数`，当前序号字号 `38px`、字重 `800`、使用当前语义色；总数字号 `25px`、使用 `#756F66`
- **标题行**：当前项的简短标题，字号 `20px`，颜色 `#1D252C`，最大宽度 `280px`，超出截断

### 切换动画

当序号从 N 切换到 N+1 时：
- 旧内容向上淡出（translateY 0 → -12px，opacity 1 → 0，0.2秒）
- 新内容从下淡入（translateY 12px → 0，opacity 0 → 1，0.2秒）

### 分镜脚本中的写法

在包含有序内容的场景中，明确标注序号指示器状态：

```
**序号指示器**：01 / 03 · 看 changelog
```

### 实现组件

使用 `SceneIndex` 组件（详见 references/05-remotion.md）：

```typescript
<SceneIndex current={1} total={3} title="看 changelog" />
```

## 字幕显示规范（CRITICAL）

完整遮挡防范规则见 [10-content-safe-area.md](10-content-safe-area.md)。生成分镜和实现代码时，必须同时满足本章节的字幕样式要求和内容安全区要求。

### 分段显示
- 使用 `AnimatedSubtitle` 组件实现分段显示
- 按中文句号（。）分割口播文案为多个段落
- 每次只显示一个段落，避免字幕覆盖场景元素
- 段落之间自动切换，无缝衔接
- 单条字幕最多 2 行；长句必须按语义拆分为连续短 segment

```typescript
<AnimatedSubtitle segments={[
  { text: "第一句话。", startTime: 0, endTime: 5 },
  { text: "第二句话。", startTime: 5, endTime: 10 },
]} />
```

### 字幕样式
- 默认位置：屏幕底部，距离底边 70px，左右各 64px
- 背景：`rgba(17, 23, 34, 0.88)`（深墨高对比）
- 边框：`1px solid rgba(255,255,255,0.2)`
- 内边距：`24px 34px`
- 圆角：`14px`
- 字号：`44-48px`
- 最小高度：`112px`，最大高度：`190px`
- 颜色：`#ffffff`
- 文字阴影：无
- 宽度：由 `left: 64px; right: 64px` 稳定约束
- 文本居中

### 字幕透明度
- 整体透明度：跟随淡入淡出动画，不要为了遮挡问题把字幕调到过低透明度
- 字幕和主体内容必须各自可读；透明度不能作为遮挡问题的主要修复手段

### 字幕动画
- 淡入：段落开始后 0.15 秒内从 opacity 0 到 1
- 淡出：段落结束前 0.15 秒内从 opacity 1 到 0
- 段落之间无缝切换

## 背景音乐规范（CRITICAL）

- 音乐文件：按需使用用户提供或获准使用的音频
- 音量：0.10（10%），确保不盖过配音
- 循环：如果音乐短于视频，需要循环播放
- 淡出：在片尾场景最后 2 秒逐渐淡出
- 推荐风格：轻快、科技感、正能量
- 实现：`<Audio src={backgroundMusic} volume={0.10} />`

## AI 配音规范（CRITICAL）

### 工具选择
使用 edge-tts 生成配音（免费、音质自然、支持中文）。

### 安装
```bash
pip3 install edge-tts
```

### 推荐语音
- `zh-CN-YunxiNeural`：男声，活泼阳光（默认推荐）
- `zh-CN-XiaoxiaoNeural`：女声，温暖
- `zh-CN-YunyangNeural`：男声，专业可靠

### 生成步骤
1. 文案生成单独的音频文件
2. 使用 `scripts/get-audio-duration.py` 获取每个音频的精确时长（帧数）
3. 根据音频时长调整场景的 `durationInFrames`
4. 确保场景时长 ≥ 配音时长，留出 0.5-1 秒缓冲

### 配音文件命名
`public/audio/scene1.mp3`, `scene2.mp3`, ...

### 配音与字幕时间同步（CRITICAL）

**生成配音时必须同时生成字幕文件（VTT）**：
```bash
edge-tts --voice zh-CN-YunxiNeural \
  --text "你的口播文案" \
  --write-media public/audio/scene1.mp3 \
  --write-subtitles public/audio/scene1.vtt
```

**从 VTT 文件中提取精确的时间戳**：
- VTT 格式示例：`00:00:00,100 --> 00:00:03,812`
- 将时间戳转换为秒：`0.1` 到 `3.812`
- 直接使用这些时间作为字幕的 `startTime` 和 `endTime`

**注意事项**：
- VTT 时间戳是毫秒精度，转换时保留 2 位小数即可
- 相邻段落的时间可以有 0.05 秒左右的重叠，确保无缝衔接
- 不要手动估算时间，必须使用 edge-tts 生成的精确时间戳

### 配音质量优化
- 语速控制：默认适中，如需调整用 `--rate=+10%` 或 `--rate=-10%`
- 停顿处理：句子间标点（。、，）自动产生停顿，`...` 产生更长停顿
- 音量平衡：配音 1.0，背景音乐 0.10，音效 0.3-0.5
