# 视频发布文案规范

## 目标

视频交付不止包含成片，还要提供一份可直接发布、与视频核心论点一致的文案。发布文案不是口播稿摘要：它要帮助观众迅速判断“这条视频为什么值得看”，同时准确承接视频中的问题、方法和结论。

## 何时生成

- AI 生成模式：成片内容和标题确认后生成。
- 真人视频模式：字幕、精华内容和最终剪辑确认后生成。
- 用户明确指定发布平台时，优先适配该平台；未指定时，默认提供适合微信视频号的版本。
- 用户后续修改视频主题、结论、封面标题或项目定位后，同步更新发布文案，避免文案与成片不一致。

## 必须交付的内容

创建项目根目录下的 `发布文案.md`，使用以下结构：

```markdown
# 发布文案

## 推荐标题
{一个可直接使用的标题}

## 备选标题
1. {备选标题一}
2. {备选标题二}

## 视频简介
{可直接粘贴发布的正文}

## 相关链接
{用户提供且与内容直接相关的项目、文章或开源地址；没有则写“无”}

## 话题标签
{5-8 个相关标签}
```

对话中向用户展示时，优先给出“推荐标题 + 视频简介 + 相关链接 + 话题标签”的可直接复制版本，不要求用户先打开文件。

## 标题规则

1. 标题要承接视频的真实矛盾或核心问题，不制造视频没有回答的悬念。
2. 优先使用“系列定位｜具体问题”结构，例如：`Agent Loop 实践｜测试通过，为什么还不等于需求通过？`
3. 系列名、专业概念只有在视频确实围绕它展开时才放入标题。
4. 推荐标题控制在一眼可读的长度；避免连续堆叠多个问号、感叹号或夸张词。
5. 备选标题应改变切入角度，而不是只替换同义词：可分别强调问题、方法或结果。

## 简介结构

简介通常采用四段式，按内容复杂度自然伸缩，不为了固定字数压缩重要逻辑：

1. **问题钩子**：用观众能理解的问题进入，不要直接开始罗列工具或 Skill。
2. **判断与意义**：给出创作者的核心判断，并说明它为什么重要。
3. **本期内容**：交代视频用什么案例、方法或工具拆解问题，以及观众能获得什么。
4. **结论与行动**：用一句可记住的结论收束；如有相关项目、开源仓库或资料，再自然引导查看。

口吻要像创作者在分享一次真实实践：清楚、自然、有判断，但不过度包装成专家口吻。默认口吻清楚、自然、有判断，不预设创作者身份。

## 链接与开源地址

- 用户提供开源地址、项目主页、文章或资料链接时，必须加入“相关链接”，并在简介结尾自然提示。
- 只能使用用户提供或已从项目配置中验证的 URL，不得猜测仓库地址。
- 保留完整原始 URL，方便平台不支持超链接时仍可复制。
- 微信视频号等平台可能不会把外部地址渲染为可点击链接，因此不要把理解正文所需的关键信息只放在链接中。
- 多个链接按“开源项目、参考文章、相关工具”的优先级排列，每行一个，避免链接淹没正文。

## 话题标签

- 默认生成 5-8 个标签，覆盖系列、主题、技术领域和内容形式。
- 标签必须与视频实际内容相关；避免使用与内容无关的热门词蹭流量。
- 用户提供的品牌标签可保留；系列内容可加入与主题相关的标签。
- 中文平台优先使用受众能识别的标签，英文术语可与中文标签搭配。

## 平台适配

### 微信视频号（默认）

- 标题清晰直接，简介保持自然分段，适合手机阅读。
- 先讲问题和价值，再放链接与标签。
- 外链使用完整 URL；不要假设链接一定可点击。

### 抖音 / 快手

- 简介更短，第一句直接呈现冲突或收益。
- 保留核心结论，减少背景铺垫；标签数量适度。

### B 站

- 可增加背景、章节看点、工具清单和资料说明。
- 标题仍需准确，不用标题党替代内容价值。

### 小红书

- 强调实践过程、个人发现和可复用经验。
- 可使用更清晰的短段落或少量列表，但避免模板化营销语。

## 质量检查

交付前逐项确认：

- [ ] 标题中的问题在视频里得到了解释或回答。
- [ ] 简介先建立问题与意义，再介绍具体 Skill、工具或步骤。
- [ ] 简介与视频最终口播、封面标题和结论一致。
- [ ] 没有为了缩短文案删掉关键逻辑。
- [ ] 用户提供的开源地址或相关链接已准确加入。
- [ ] 没有编造数据、案例、功能或 URL。
- [ ] 话题标签与内容相关，数量适中。
- [ ] 文件编码为 UTF-8 且不含 BOM。
