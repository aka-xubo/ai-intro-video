# 内容安全区与字幕遮挡防范

## 目标

字幕不能遮挡主体内容。遇到字幕量大、句子长、VTT 自动切分不理想时，优先处理字幕文本和布局预算，而不是简单把字幕下移、调透明或压在画面上。

这份规范适用于所有 Remotion 视频项目，包括 AI 生成视频和真人视频后期。

---

## 核心原则

### 四层防御

1. **字幕预算**：每条字幕最多 2 行，优先控制文本长度。
2. **内容安全区**：主体内容不得进入字幕预留区。
3. **场景避让**：底部有关键内容时，字幕切换到更合适的位置或缩小展示。
4. **验证门禁**：生成后必须检查长字幕和低位内容冲突。

透明度只能降低遮挡感，不能作为主要解决方案。

---

## 画布分区

默认以 1080 x 1920 竖屏为基准：

```text
Y=0
┌─────────────────────────────────────┐
│ 顶部阶段区 0-160                    │
│ 阶段条、序号、角标、小型状态信息       │
├─────────────────────────────────────┤
│ 主体内容区 160-1380                 │
│ 标题、卡片、流程图、截图、人物        │
├─────────────────────────────────────┤
│ 主体/字幕缓冲区 1380-1450           │
├─────────────────────────────────────┤
│ 字幕预留区 1450-1850                │
│ 字幕容器、关键词字幕                 │
├─────────────────────────────────────┤
│ 底部边距 1850-1920                  │
└─────────────────────────────────────┘
```

### 布局硬规则

- 使用 `bottom` 定位的主体内容：`bottom >= subtitleReserve + 24`。
- 默认字幕预留高度：`subtitleReserve = 470`。
- 如果字幕字号大于 48、padding 更大、或可能出现 3 行：先拆字幕，不允许侵占主体区。
- 使用 `top + height` 定位时，主体内容底边必须 `<= 1380`。
- 截图、流程图、对比卡、结论大字、人物头部等关键信息不能落在 `Y >= 1450`。
- 横屏项目按画布高度等比例换算这些边界，不直接套用竖屏像素值。

示例：

```tsx
// 正确：主体内容避开字幕区
<div style={{ position: "absolute", bottom: 540 }} />

// 错误：主体内容会和默认字幕区冲突
<div style={{ position: "absolute", bottom: 120 }} />
```

## 字幕预算

### 单条字幕长度

默认样式下：

- 字号：44-48px。
- 行高：1.35-1.5。
- 最大宽度：屏幕宽度的 86%-92%。
- 单行中文建议不超过 28-32 字。
- 单条字幕建议不超过 42-48 个中文字符。
- 严禁为了保留整句而让字幕超过 2 行。

### 文本切分规则

从 VTT 或 SRT 生成字幕 segments 后，必须做二次整理：

1. 优先按语义切分：逗号、顿号、分号、短停顿。
2. 长句拆成两个连续短 segment，时间按字符数或词组比例分配。
3. 删除口播中不影响理解的填充词，例如“其实”“然后”“那么”。
4. 屏幕上已经有的大标题、关键词，不要在字幕里重复完整表达。
5. 一条字幕只表达一个信息点。

示例：

```tsx
// 不推荐：容易变成 3 行
{ text: "最有意思的是，报告发现，真正的AI变革不是自上而下推动的，而是从超级个体开始，逐步扩散形成超级团队的。", startTime: 0, endTime: 6 }

// 推荐：拆成两个短 segment
{ text: "真正的 AI 变革，不是自上而下推动。", startTime: 0, endTime: 3.1 }
{ text: "它是从超级个体开始，扩散成超级团队。", startTime: 3.1, endTime: 6 }
```

## 字幕组件规范

### 推荐默认样式

```tsx
const subtitleStyle: React.CSSProperties = {
  position: "absolute",
  bottom: 70,
  left: 64,
  right: 64,
  minHeight: 112,
  maxHeight: 190,
  padding: "24px 34px",
  background: "rgba(17, 23, 34, 0.88)",
  border: "1px solid rgba(255,255,255,0.2)",
  borderRadius: 14,
  overflow: "hidden",
  textAlign: "center",
};
```

文字样式：

```tsx
const subtitleTextStyle: React.CSSProperties = {
  fontSize: 42,
  lineHeight: 1.42,
  whiteSpace: "pre-wrap",
  wordBreak: "keep-all",
  overflowWrap: "break-word",
};
```

### 不推荐做法

- 不要把字幕 `bottom` 改到 0-20px 来“让出空间”。这会挤压安全边距，也无法解决长字幕高度问题。
- 不要只把字幕透明度调低。字幕仍会覆盖视觉层级，且会降低字幕可读性。
- 不要允许字幕无限增高。容器必须有 `maxHeight`，文本必须被拆分。

## 场景避让策略

### 默认：字幕底部显示

当主体内容集中在中上部或中心，使用默认底部字幕。

### 底部内容密集：主体上移

流程图、横向卡片、结论按钮、人物半身等内容靠近底部时，优先把主体上移：

```tsx
<div style={{ position: "absolute", bottom: 540 }} />
```

### 无法上移：切换字幕布局

如果主体必须占据底部，使用以下备选之一：

- **top-caption**：字幕放在顶部 170-390 区域，主体在中下部，并避开阶段条。
- **side-caption**：字幕放左/右侧窄栏，主体保留另一侧。
- **compact-caption**：字号降到 38-42，容器宽度增加，仍限制 2 行。
- **keyword-only**：画面已有说明时，字幕只保留关键词或短句。

每个场景只选一种策略，避免字幕位置频繁跳动。

---

## 分镜脚本要求

每个镜头必须增加“字幕安全”字段：

```text
字幕安全：bottom-caption，主体内容底边 <= 1380，字幕最长 2 行
```

可选值：

- `bottom-caption`：默认底部字幕。
- `top-caption`：顶部字幕。
- `side-caption`：侧边字幕。
- `compact-caption`：紧凑字幕。
- `keyword-only`：仅显示关键词字幕。

如果镜头包含流程图、截图、对比卡、人物、底部结论区，必须明确主体内容的底边位置或 `bottom` 值。

## 实现检查

生成 Remotion 项目后，必须执行两类检查。

### 1. 静态检查

```bash
python3 ../ai-intro-video/scripts/check-subtitle-safe-area.py src public/audio
```

检查内容：

- TSX 中疑似低位 `bottom` 定位。
- VTT/SRT 中过长字幕。
- 可能超过 2 行的字幕。

### 2. 视觉检查

在 Remotion Studio 中检查：

- 字幕最多 2 行。
- 字幕出现时不遮挡标题、流程图、卡片、人物脸部、关键数字。
- 底部主体内容与字幕之间至少 24px 间距。
- 字幕位置在同一场景内保持稳定。

## 当前问题的推荐修复

截图中的问题属于“长字幕 + 底部主体内容冲突”。推荐处理顺序：

1. 把长字幕拆成 2 个短 segment，每段最多 2 行。
2. 将底部流程内容整体上移，主体底边保持在 `Y <= 1380`。
3. 字幕恢复到稳定底部位置，如 `bottom: 70`，不要贴底。
4. 如果画面信息必须放底部，改为 `top-caption` 或 `compact-caption`。

---

## 验收标准

- 没有一条字幕超过 2 行。
- 没有主体关键内容进入 `Y >= 1450`。
- 没有 `bottom < 470` 的主体内容，除非该元素明确标注为背景、装饰或非关键信息。
- 长口播被拆分为连续短字幕，不牺牲语义。
- 预览中字幕与画面内容均可独立读清。
