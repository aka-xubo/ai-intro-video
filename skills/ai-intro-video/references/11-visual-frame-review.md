# 抽帧视觉检查与自动优化

## 目标

在视频交付前,用 Remotion still 渲染关键帧截图,检查每个场景的文字、动画、排版、截图、字幕和主体信息是否合理。发现问题后必须自动修改场景代码并重新抽帧复查,不是只输出问题清单。

## 渲染浏览器

使用当前机器上与平台匹配的 Chrome Headless Shell，并把实际路径传给 Remotion CLI 的 `--browser-executable` 参数。未安装时可在项目中运行 `npx remotion browser ensure`。

## 抽帧命令

在 Remotion 项目根目录执行:

```bash
CHROME_HEADLESS_SHELL="{当前机器上 Chrome Headless Shell 的路径}"
mkdir -p out/visual-check
npx remotion still <entry> <composition-id> out/visual-check/frame-0000.png \
  --frame=0 \
  --browser-executable="$CHROME_HEADLESS_SHELL" \
  --overwrite
```

常见参数:

- `<entry>`: 通常是 `src/index.ts` 或项目实际入口。
- `<composition-id>`: `Root.tsx` 中的 Composition id。
- `--frame`: 要抽取的帧号。
- `--browser-executable`: 必须指向内置 chrome-headless-shell。

## 抽帧策略

必须覆盖每个场景的关键视觉状态:

1. 场景开始后 0.5 秒: 检查入场状态,避免空白、素材缺失、首屏文字错位。
2. 场景 30% 位置: 检查主要布局和第一组动画稳定态。
3. 场景 60% 位置: 检查中段信息密度、字幕和主体关系。
4. 场景结束前 0.5 秒: 检查出场状态和下一个场景切换前是否仍可读。

如果场景包含列表、截图放大、关键词高亮、流程图、人物/产品图,必须额外抽取这些元素出现后的 3-5 帧。

## 检查标准

逐张截图检查以下问题:

- **文字可读性**: 字号足够,不糊,不被裁切,不压边,不出现超长单行。
- **文字层级**: 标题、重点词、解释文字层级清晰,同屏文本不抢焦点。
- **字幕关系**: 字幕不遮挡主体,主体底边不进入字幕预留区。
- **排版平衡**: 元素之间有明确间距,没有拥挤、漂浮、左右失衡或卡片堆叠过密。
- **动画状态**: 抽到中间帧时元素不应半透明到不可读、错位、重叠或停在尴尬位置。
- **截图/图片展示**: 截图关键区域清晰,不被过度裁切,不被暗色遮罩或装饰挡住。
- **视觉主题一致性**: 字体、颜色、圆角、阴影、图标风格和品牌规范一致。
- **默认风格一致性**: 用户未指定其他风格时，按视觉风格规范检查；主体应保持暖纸、深墨宋体标题、等宽标签、语义色边线和克制动效。
- **画面完整性**: 不允许空白帧、黑屏、资源加载失败、明显报错文本或默认占位。
- **移动安全感**: 如果画面元素会移动,关键文字和主体在运动过程中仍应可读。

## 自动修复流程

发现任一视觉问题时,立即修改场景代码:

1. 定位截图对应的场景和帧号。
2. 修改布局、字号、行高、容器宽度、动画时间、字幕策略、截图裁切或主体位置。
3. 保持修复范围局限于相关场景和共享组件,不要做无关重构。
4. 重新运行同一批 still 抽帧命令。
5. 再次检查截图,直到所有关键帧可读、清晰、稳定。

禁止只把视觉问题列表交给用户后停止。视觉检查是交付门禁,失败时必须自动修复并复验。

## 常见修复动作

- 文字出界: 降低字号、增加换行、限制 `maxWidth`、调整 `lineHeight`。
- 文本过多: 压缩文案,拆成多段出现,或改为关键词高亮。
- 字幕遮挡主体: 上移主体,改 `top-caption` / `side-caption` / `compact-caption` / `keyword-only`。
- 动画中间态重叠: 错开入场时间,缩短位移距离,增加稳定停留段。
- 截图看不清: 放大关键区域,裁切无关边缘,提高截图容器尺寸。
- 画面空: 提前关键元素入场,缩短空白过渡,增加背景信息但不堆装饰。
- 对比度不足: 调整文字颜色、背景亮度、遮罩透明度或描边阴影。

## 交付前检查口径

最终回复前必须确认:

- 已抽取每个场景的关键帧。
- 已修复所有文字、动画、排版、截图和字幕遮挡问题。
- 已重新抽帧复查通过。
- 已通过时长验证和 TypeScript 检查。
